# Konthora — Launch Checklist

A step-by-step checklist for taking Konthora live. Work through the items top to
bottom. See [DEPLOYMENT.md](DEPLOYMENT.md) for the technical details and
[deploy/MONITORING.md](deploy/MONITORING.md) for monitoring guidance.

> Domains used throughout: `konthora.dev.bd` (frontend / Vercel) and
> `api.konthora.dev.bd` (backend / VPS). Swap these if you use different domains.

---

## 1. Domain

- [ ] Register `konthora.dev.bd` with a registrar.
- [ ] Verify you control the domain (registrar dashboard + email ownership).
- [ ] Decide the exact hostnames: `konthora.dev.bd` and `api.konthora.dev.bd`.

## 2. DNS

- [ ] Add an **A record** for `api.konthora.dev.bd` → VPS public IP.
      (example: `A api 203.0.113.10`, TTL 3600)
- [ ] Add an **A/AAAA record** for `konthora.dev.bd` → Vercel's IP
      (or use `cname.vercel-dns.com` via a CNAME / ALIAS record).
- [ ] Add a **CNAME** for `www.konthora.dev.bd` → `konthora.dev.bd` (optional).
- [ ] Wait for DNS propagation: `nslookup api.konthora.dev.bd` returns the VPS IP.
- [ ] (Recommended) Add `_dmarc`, `_spf` (or DKIM via the mail provider) and a
      custom `MX` if you send email from this domain.

## 3. Cloudflare (optional)

- [ ] Add the domain to Cloudflare and set nameservers at the registrar.
- [ ] Proxied ("orange cloud") DNS for `api.konthora.dev.bd` — Cloudflare handles
      DDoS filtering and provides TLS in front of Nginx.
- [ ] Set TLS mode to **Full (strict)** so Cloudflare→Nginx traffic is encrypted.
- [ ] Ensure Cloudflare does **not** strip the `Authorization` header
      (default setting is fine; do not enable "remove headers").
- [ ] Whitelist Cloudflare's IP ranges in UFW (`ufw allow from <cf-ip>`).

## 4. SSL / TLS

- [ ] Certificate for `api.konthora.dev.bd` obtained via Let's Encrypt
      (the deploy script does this: `deploy.sh`).
- [ ] Auto-renewal active: `sudo certbot renew --dry-run` succeeds.
- [ ] Certificate renewal reloads Nginx (certbot nginx plugin reloads it).
- [ ] HSTS enabled (backend sets it in `APP_ENV=production`; Nginx also sets it).
- [ ] Verify at https://www.ssllabs.com/ssltest — grade A or better.

## 5. Vercel (frontend)

- [ ] Import the GitHub repository `DevBySharif/konthora` into a Vercel project.
- [ ] Framework preset: **Next.js** (auto-detected).
- [ ] Root directory: `/`; build command `npm run build`; output `Next.js (static)`.
- [ ] Add production **Environment Variables**:
      - `NEXT_PUBLIC_SITE_URL=https://konthora.dev.bd`
      - `NEXT_PUBLIC_CONTACT_EMAIL=hello@konthora.dev.bd`
      - `NEXT_PUBLIC_API_URL=https://api.konthora.dev.bd/api/v1`
- [ ] Add `konthora.dev.bd` (and `www.`) as production domains in Vercel.
- [ ] First production deployment succeeds; check `https://konthora.dev.bd/sitemap.xml`
      and `/robots.txt` resolve.

## 6. VPS (backend)

- [ ] Ubuntu 24.04 server with a public IPv4 (2+ vCPU, 4 GB RAM recommended).
- [ ] SSH key access enabled; password auth disabled.
- [ ] `api.konthora.dev.bd` DNS A record points at the VPS.
- [ ] Run the provisioning script: `sudo bash deploy/scripts/deploy.sh`.
- [ ] Verify `https://api.konthora.dev.bd/api/v1/health` returns
      `{"status":"alive", ...}`.
- [ ] Firewall open only: 22 (SSH), 80, 443. Everything else closed.

## 7. Environment variables

- [ ] **Frontend (Vercel):** all three `NEXT_PUBLIC_*` variables set (above).
- [ ] **Backend (VPS):** `/etc/konthora/konthora.env` exists (mode 600) and has:
      - `APP_ENV=production`
      - `CORS_ORIGINS=https://konthora.dev.bd`
      - `TRUST_PROXY_HEADERS=true`
      - `TRUSTED_HOSTS=api.konthora.dev.bd`
      - `TTS_STORAGE_ROOT=/opt/konthora/repo/backend/storage`
      - `LOG_DIR=/var/log/konthora`
- [ ] CORS origin in backend exactly matches the frontend `NEXT_PUBLIC_SITE_URL`.

## 8. GitHub

- [ ] Repository is public: https://github.com/DevBySharif/konthora.
- [ ] CI passes on `main` (Actions tab — backend + frontend jobs green).
- [ ] Branch protection on `main`: require CI checks + a pull request to merge.
- [ ] No secrets committed: `.env`, `konthora.env`, certificates are gitignored.
- [ ] `README.md` renders correctly with accurate deployment links.

## 9. Search Console

- [ ] Add `https://konthora.dev.bd` (Domain property) in Google Search Console.
- [ ] Verify ownership (DNS TXT or HTML meta tag).
- [ ] Submit `https://konthora.dev.bd/sitemap.xml`.
- [ ] Request indexing for `/`, `/text-to-speech`, `/audio-to-text` once live.

## 10. Bing Webmaster Tools

- [ ] Add the site in Bing Webmaster Tools.
- [ ] Verify ownership (import from Google Search Console or DNS/HTML).
- [ ] Submit `https://konthora.dev.bd/sitemap.xml`.

## 11. robots.txt

- [ ] `/robots.txt` is served with `sitemap: https://konthora.dev.bd/sitemap.xml`
      (generated by `src/app/robots.ts`).
- [ ] `/api` is not blocked (the frontend calls it cross-origin from the browser;
      robots.txt only affects the Vercel host anyway).
- [ ] Confirm the URL in the file matches the live domain.

## 12. sitemap.xml

- [ ] `/sitemap.xml` lists all 8 pages (home, tools, legal, contact).
- [ ] URLs use `https://konthora.dev.bd` (no `localhost`).
- [ ] Google/Bing can fetch it (no robots blocking).

## 13. Favicon

- [ ] `/favicon.ico` exists and renders in the browser tab
      (present at `src/app/favicon.ico`).
- [ ] Manifest references `/favicon.ico` (`src/app/manifest.ts`).

## 14. Open Graph

- [ ] `og:title`, `og:description`, `og:url`, `og:site_name`, `og:type` on every page
      (via `src/lib/metadata.ts`).
- [ ] `og:image` generated per page (`src/app/opengraph-image.tsx`).
- [ ] Check with https://www.opengraph.xyz or the Facebook Sharing Debugger.

## 15. Twitter Card

- [ ] `twitter:card = summary_large_image`, `twitter:title`, `twitter:description`
      on every page.
- [ ] `twitter:image` generated (`src/app/twitter-image.tsx`).
- [ ] Validate with https://cards-dev.twitter.com/validator (or the preview in X).

## 16. Monitoring

- [ ] UptimeRobot / Better Stack heartbeat on
      `https://api.konthora.dev.bd/api/v1/health`.
- [ ] Disk/RAM/CPU alerts configured (see deploy/MONITORING.md).
- [ ] Alert email/slack/webhook configured.

## 17. Backups

- [ ] Run `sudo bash deploy/scripts/backup.sh` once manually.
- [ ] Schedule a nightly cron: `0 2 * * * bash /opt/konthora/repo/deploy/scripts/backup.sh`
- [ ] Verify a restore path exists (extract `backups/config-*.tar.gz`).

---

## Post-launch

- [ ] Verify a real TTS job end-to-end on `https://konthora.dev.bd/text-to-speech`.
- [ ] Verify a real transcription upload on `https://konthora.dev.bd/audio-to-text`
      (MP3 → SRT with timestamps).
- [ ] Confirm rate-limit 429 responses are friendly (wait, then retry).
- [ ] Watch first-day error logs: `journalctl -u konthora -f`.
